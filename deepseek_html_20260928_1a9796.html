3. Proceso inverso (descifrado geométrico)

Cómo funciona la inversión

Dado el valor final \(x_{\text{final}}\), el segmento inicial \(x_0\) y la secuencia de figuras: 

D = x_0 − x_final  =  Σ  d_i / (f_0 · f_1 · ... · f_i)
Multiplicando por Q = f_0 · f_1 · ... · f_7:
N = D · Q = d_0·Q_1 + d_1·Q_2 + ... + d_7·Q_8
donde Q_{i+1} = f_{i+1} · ... · f_7,  Q_8 = 1.

Despeje desde el dígito menos significativo:
  d_7 = N mod f_7
  N   = (N − d_7) / f_7
  d_6 = N mod f_6
  N   = (N − d_6) / f_6
  ... hasta d_0.

Cada d_i ∈ {1, 2}. Bit b_i = d_i − 1 ∈ {0, 1}.

5. ⚠️ Seguridad: qué hay que ocultar

La clave geométrica son tres cosas

ElementoEspacio de búsquedaBits de entropía
Secuencia de figuras6⁸ ≈ 1,7 M~21 bits
Segmento inicial exactoDepende de decimales~10–30 bits
Orden de bits (MSB/LSB)21 bit
Total~32–52 bits

Qué pasa si ocultas los datos de entrada

  • Sin la secuencia: no sabes con qué figura dividir en cada paso.
  • Sin el segmento inicial: no sabes de dónde parte la deducción.
  • Sin el orden de bits: la reconstrucción es ambigua.
  • Un atacante que intercepte el paquete cifrado solo ve fracciones gigantes sin sentido geométrico.

PERO: esto es ofuscación, no cifrado

ADVERTENCIA La clave geométrica tiene solo ~32–52 bits de entropía. Un atacante con fuerza bruta moderna la rompe en minutos u horas. NO es seguro frente a criptoanálisis.

Para seguridad real, hay que cifrar la clave geométrica (secuencia + segmento + orden) con AES-256 o derivarla de una contraseña con PBKDF2 / Argon2. Así el atacante no solo debe romper la geometría, sino primero el cifrado estándar.

Estrategia de seguridad recomendada

  1. Capa 1 (geométrica): codifica el mensaje con Tales 3-5-... usando una secuencia secreta.
  2. Capa 2 (clave): cifra la secuencia + segmento + orden con AES-256-GCM usando una contraseña fuerte.
  3. Capa 3 (transporte): envía paquete geométrico + clave cifrada + nonce por un canal seguro.
  4. Rotación: cambia la secuencia geométrica por sesión.

Qué NO hacer

  • ❌ Publicar la secuencia de figuras.
  • ❌ Publicar el segmento inicial exacto.
  • ❌ Usar la misma secuencia para todos los mensajes.
  • ❌ Confundir ofuscación con cifrado.
  • ❌ Confiar en que el atacante no conoce el algoritmo (Kerckhoffs).

Qué SÍ hacer

  • ✅ Cifrar la clave geométrica con AES-256-GCM.
  • ✅ Derivar la clave de una contraseña con PBKDF2 (100k+ iteraciones).
  • ✅ Rotar secuencias por sesión.
  • ✅ Verificar el tag GCM antes de decodificar geometría.
  • ✅ Auditar con benchmarks reproducibles.

6. Análisis de valor

Qué es real

  • Biyección exacta byte → racional único. Reversible con BigInt.
  • Sin IEEE: sin drift, sin redondeo.
  • Proceso inverso: despeje desde el dígito menos significativo, O(8) por byte.
  • AES-GCM 256: cifrado autenticado real.
  • Visualización: cada paso geométrico es auditable.

Qué NO es

  • No comprime: el criptograma es mayor que el plaintext.
  • No encripta por sí solo: la geometría es pública.
  • No supera a Shannon: |imagen| ≤ |dominio|.
  • No es seguro sin AES encima: la clave geométrica es pequeña.
