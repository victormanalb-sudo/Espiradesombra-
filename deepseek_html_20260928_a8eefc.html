3. Receptor: paquete mínimo → mensaje

Cómo funciona la inversión con paquete mínimo

El paquete solo contiene:
  { N_i }            ← enteros por byte
  { clave_cifrada }  ← AES-GCM(secuencia + start + orden)

El receptor:
  1. Descifra la clave con su contraseña.
  2. Reconstruye Q_0 = f_0 · f_1 · ... · f_7.
  3. Calcula start − N_i / Q_0 = resto final.
  4. Despeja d_7 = N mod f_7, N = (N − d_7) / f_7, ...
  5. Bits b_i = d_i − 1 → byte.

5. Seguridad: por qué no se pueden deducir los parámetros

Ataque sin clave

El atacante intercepta: 

[17809, 24829, 32761, 27889, 33461, 36629, 35641, 35281, ...]
[base64: salt||iv||ciphertext||tag]

Intenta deducir la secuencia de figuras y el segmento inicial probando combinaciones. Pero no sabe cuántos bytes hay ni qué figura corresponde a cada paso. El espacio de claves es:

ParámetroEspacioBits
Secuencia (8 posiciones × 6 figuras)6⁸ ≈ 1,68 M~21
Segmento inicial (decimales)~10⁶~20
Orden de bits (MSB/LSB)21
Total~42 bits

Ataque con clave cifrada

La clave se cifra con AES-256-GCM (NIST). El atacante ahora necesita:

  1. Romper AES-256 → inviable (~2²⁵⁶).
  2. Romper PBKDF2-SHA256 (100.000 iteraciones) → coste alto.
  3. Encontrar la contraseña → depende de su fortaleza.

Qué oculta el paquete mínimo

  • ✅ No revela la secuencia de figuras.
  • ✅ No revela el segmento inicial.
  • ✅ No revela los dígitos d_i intermedios.
  • ✅ No revela el orden de bits.
  • ✅ No revela cuántos pasos se dieron.
  • ✅ Los N parecen aleatorios sin la clave.

Qué NO oculta

  • ❌ El número de bytes (longitud del array).
  • ❌ El rango de los N (pistas sobre las figuras).
  • ❌ La existencia del esquema geométrico (Kerckhoffs).
  • ❌ Metadatos del canal (timing, tamaño, etc.).

Recomendaciones

  • ✅ Rotar la secuencia geométrica por sesión.
  • ✅ Usar contraseña fuerte (>16 caracteres, aleatoria).
  • ✅ Añadir padding aleatorio a los N para ocultar rango.
  • ✅ Verificar el tag GCM antes de decodificar.
  • ✅ No reutilizar salt ni iv.

6. Análisis de valor

Qué es real

  • Paquete mínimo: solo N por byte, sin pasos intermedios.
  • Clave cifrada: AES-256-GCM sobre la clave geométrica.
  • Sin clave → ruido: los N no permiten deducir nada útil.
  • BigInt exacto: sin drift de IEEE.
  • Proceso inverso: despeje O(8) por byte.

Qué NO es

  • No comprime: expande ~4×.
  • No es cifrado por sí solo: necesita AES encima.
  • No supera a Shannon.
  • No oculta la longitud del mensaje.
