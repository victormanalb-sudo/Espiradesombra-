Brief para Grok — AntiPC Runtime

Especificación técnica para generación de código. Copia por fases, no todo de golpe.

Reglas para Grok

  1. No generar código sin métricas. Cada módulo debe incluir cómo medirlo.
  2. No inventar dependencias. Solo C++20 estándar + winsock2 / POSIX sockets.
  3. No decir "esto revoluciona". Solo hechos verificables.
  4. No generar todo de golpe. Por fases, esperar confirmación.
  5. Compilable. g++ -O3 -std=c++20 -pthread sin errores.
  6. Sin frameworks externos. Nada de Boost, Qt, LLVM.
  7. Cada respuesta ≤ 300 líneas. Si hace falta más, dividir.

Fase 1 — Documento de arquitectura

FASE 1

Entregable

Documento de 10 páginas máximo. Sin código.

Contenido

  • Problema: la CPU gasta ciclos gestionando red, copias de memoria y saltos condicionales.
  • Hipótesis: una arquitectura de flujo distribuido con buffer lock-free, ingesta zero-copy y motor branchless reduce la carga de CPU frente a una arquitectura secuencial equivalente.
  • Diseño: buffer circular, UDP no bloqueante, Grafcet algebraico, matriz de existencia, redundancia topológica.
  • Métricas: CPU %, latencia μs, throughput paquetes/s, temperatura °C.
  • Limitaciones: no comprime, no encripta, requiere programación de bajo nivel.

Prompt exacto

Genera un documento técnico de 10 páginas máximo sobre la arquitectura AntiPC (Adaptive Network Through Parallel Computing). Sin código. Secciones: Problema, Hipótesis, Diseño, Métricas, Limitaciones. En español. Sin exageraciones. Sin decir "revoluciona". Solo hechos verificables y medibles.

Prompt exacto

Genera el módulo de buffer circular lock-free en C++20. Requisitos:
- Sin malloc en runtime. Memoria pre-asignada.
- Atómicos con memory_order_acquire/release.
- Alineado a 64 bytes (línea de caché).
- ≤ 150 líneas.
- Incluir main() mínimo para probarlo.
- Compilable con: g++ -O3 -std=c++20 -pthread
- Sin dependencias externas.
Solo el código y un comentario de cómo medirlo con perf stat.

Prompt Fase 2 — Ingesta UDP

Añade al runtime anterior el módulo de ingesta UDP no bloqueante. Requisitos:
- Socket AF_INET, SOCK_DGRAM, IPPROTO_UDP.
- FIONBIO para no bloqueante.
- recvfrom() escribiendo directamente en el buffer circular (zero-copy).
- Compatible Windows (winsock2) y Linux (POSIX).
- ≤ 150 líneas.
- Compilable con g++ -O3 -std=c++20 -pthread.
Solo el código y un comentario de cómo medir paquetes/s.

Prompt Fase 2 — Motor Grafcet

Añade al runtime el motor Grafcet branchless. Requisitos:
- 3 etapas (X0, X1, X2) en one-hot.
- Máscara de existencia EXISTENCE_MASK = X0|X1|X2.
- Colapso por LSB: state & (-state).
- Ecuaciones: X_n(t+1) = (X_n & ~T_n) | (X_{n-1} & T_{n-1}).
- Cero if/else en el bucle crítico.
- ≤ 150 líneas.
- Compilable con g++ -O3 -std=c++20 -pthread.
Solo el código y un comentario de cómo verificar la autocuración inyectando un estado corrupto.

Prompt exacto

Genera dos programas C++20 que midan lo mismo:
1. arquitectura_clasica.cpp: recibe UDP, copia con memcpy a un vector, procesa con if/else.
2. antipc_runtime.cpp: recvfrom directo al buffer circular, motor branchless.

Ambos deben:
- Correr 10 segundos.
- Imprimir: paquetes procesados, CPU % (con clock()), latencia media en μs.

Al final, un script bash benchmark.sh que compile ambos, los ejecute y compare resultados con perf stat.
