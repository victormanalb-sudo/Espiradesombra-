3. Receptor: 1 fracción → mensaje

Por qué funciona

Emisor:
  x_0 = 1.33
  x_1 = x_0 − d_0 / f_0
  x_2 = x_1 − d_1 / (f_0·f_1)
  x_3 = x_2 − d_2 / (f_0·f_1·f_2)
  ...
  x_n = x_{n−1} − d_{n−1} / (f_0·...·f_{n−1})

  Solo se transmite x_n.

Receptor:
  N = (x_0 − x_n) · (f_0·f_1·...·f_{n−1})
  d_{n−1} = N mod f_{n−1}
  N = (N − d_{n−1}) / f_{n−1}
  d_{n−2} = N mod f_{n−2}
  ...
  d_0 = N (último)
  bits b_i = d_i − 1

Necesita saber:
  · la fracción x_n
  · el inicio x_0
  · la secuencia f_i
  · la longitud n (en bits)

5. Seguridad

Qué sigue siendo necesario ocultar

  • Secuencia de figuras (~21 bits).
  • Segmento inicial (~10–30 bits).
  • Orden de bits (1 bit).
  • Longitud del mensaje (metadato, no secreto pero revela tamaño).

Sin la clave

El atacante ve solo la fracción final. Sin saber la secuencia y el inicio, no puede invertir. La fracción parece un número aleatorio entre 0 y 1.33.

Con la clave pública

Si la secuencia y el inicio son conocidos, cualquiera invierte y obtiene el mensaje. Por eso hay que cifrar la clave con AES-GCM o derivarla de una contraseña.

Mejoras recomendadas

  • Rotar la secuencia por sesión.
  • Cifrar la clave con AES-256-GCM.
  • Añadir padding aleatorio antes de codificar (oculta longitud real).
  • Usar un terminador simbólico en lugar de transmitir la longitud.
