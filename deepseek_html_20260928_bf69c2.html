1. Codificador geométrico (Tales 3-5 alternando)

Principio matemático

Cada byte se descompone en 8 decisiones binarias. Cada decisión elige un dígito \(d_i \in \{1, 2\}\) sobre una base alternante \(b_i \in \{3, 5\}\). El valor exacto es: 

x = Σ d_i / (b_1 · b_2 · ... · b_i)   con   d_i ∈ {1,2},  b_i ∈ {3,5,3,5,...}

Rango: \([3/7, 6/7] \approx [0.4286, 0.8571]\). Biyección exacta: cada byte → una fracción racional única. Sin IEEE, sin drift. Todo con BigInt.

2. Cifrado AES-GCM sobre la representación geométrica

La codificación geométrica no es cifrado. Es una biyección pública. Para cifrar de verdad, se aplica AES-GCM 256 sobre la secuencia de bytes. El resultado es un criptograma autenticado (confidencialidad + integridad).

3. Análisis de valor

Qué es real

  • Biyección geométrica: cada byte → un racional único en [3/7, 6/7]. Único, invertible, exacto.
  • Aritmética BigInt: sin drift de IEEE. Apto para sistemas que exigen exactitud (control industrial, finanzas, CAD).
  • AES-GCM 256: cifrado autenticado estándar (NIST). Confidencialidad + integridad.
  • Derivación de clave: PBKDF2-SHA256 con 100.000 iteraciones. Resistente a fuerza bruta básica.
  • Visualización: representación geométrica legible. Útil para auditar, educar, depurar.

Qué NO es

  • No es compresión. El criptograma es mayor que el plaintext (IV + tag + salt).
  • No es "encriptación geométrica" por sí sola. La geometría es pública.
  • No supera a Shannon. \(|\text{imagen}| \le |\text{dominio}|\).
  • No sustituye a AES ni a ChaCha20. Solo los envuelve con una representación novedosa.

4. Referencia matemática

Fórmula exacta

Dado un byte B = (b_0, b_1, ..., b_7) con b_i ∈ {0,1}:
  d_i = b_i + 1  ∈ {1, 2}
  base_i = 3 si i es par, 5 si i es impar
  x = Σ_{i=0}^{7}  d_i / ∏_{k=0}^{i} base_k

El racional x se representa como (numerador, denominador) con BigInt.
Decodificación: división euclidiana recursiva sobre x.
  Resto de x respecto a 1/3 → primer dígito.
  Repetir sobre el resto con base 5, luego 3, luego 5...
